# Peer review — LLM lab (llm_lab_pkg) — 2026-08-27

Guided subagent review; editor's synthesis. Method: static equation-to-code audit;
numerical gradient check against finite differences (criterion stated before the run);
reproduction of handout numbers through `llm_lab_core.m` on this machine (MATLAB

scripts' figure paths were not executed. The reviewer's scripts are in the session

## Summary

The mathematics of the lab is correct and the structural results the chapter leans on
reproduce exactly; the handout is not currently a trustworthy claims document —
roughly a third of its quantitative tables do not come out of the shipped code, one
demo script crashes on plausible audience input, and its most quotable sentence is
contradicted by its own table. Sound instrument, stale documentation.

## What is verified sound

- **Gradient check: PASS.** Central finite differences, h = 1e-6, criterion
  max relative error < 1e-6, stated before running. Result per layer (weights /
  biases): 1.338e-08 / 6.137e-10, 7.596e-08 / 1.815e-09, 2.065e-09 / 3.123e-09.
  The backward pass in `llm_lab.m:162–167` (and the identical core) is exact,
  including the tanh derivative and the pre-update gradient ordering.
- **Reproduced bit-for-bit:** parameter counts (2957 digit; 34232 word); E1's
  100 %/0 % digit-vs-word split on all three seeds; E3's random-split mean 66.6667;
  the E4 depth-0 column (4.0 at every width — structurally guaranteed, since DEPTH=0
  never touches WIDTH); the superseded convexity check (GD 0.375549 vs closed-form
  0.373699, gap 1.85e-03). These carry the chapter's core argument.
- The entropy probe, `<eos>` training logic, and `pad_ctx` windowing do what their
  comments claim; the capstone's whitelist rule parser rejects injection attempts
  before any evaluation.

## Findings

**Blocker — stale numbers under a reproducibility claim.** The handout opens with
"every number was produced by running the code"; on this machine the shipped code
does not produce: E2 x+7/parity (3.33 % vs claimed 10.7 %; per-token 96.67/50.67/31.33
vs 95/37/55), E5 (77.55/80.00 and 61.90/66.67 vs 84.4/86.7 and 66.0/70.0), the entire
Seeds loss table, the ETA milestones (190/944/3144 vs 180/897/2987), and E4's
width-512 count (47117 vs "~130,000" — the "26×" headline is actually 9.3×). The
reproducing/failing pattern points to numbers generated by an earlier code state, not
platform RNG (runs consuming extra RNG reproduce exactly; runs consuming none do
not). **Action adopted: regenerate every slide-bound number from the shipped code on
the presentation machine before any slide quotes it; until then no handout number is
quotable.**

**Major — capstone crash.** `make_fmt` (`llm_lab_compare.m:137–152`) space-pads
mixed-sign outputs; `' '` is not a vocabulary key, so audience-typed rules such as
`x-50` or `log(x)-2` kill the live demo with a container-key error (verified on
verbatim copies). Fix: zero-pad inside the sign, or reject mixed-sign rules with a
message.

**Major — E2's narrative contradicts its own table.** "The ones digit is always
near-perfect… all failure lives in the tens digit" fails against the handout's own
rows (ones = 55 for x+7, 46 for x²) and against reproduction (ones = 31.33 for x+7).
The defensible statement: failure concentrates at the carry position *and propagates
forward through autoregressive decoding* — a tens error corrupts the context the ones
prediction conditions on. The carry-parity confound premise is verified by counting
(train 0.625/0.800 flips to 0.800/0.600 on test); the claim that the model *uses* the
confound has no supporting analysis in the package and must be downgraded from
"verified" to "consistent with".

**Major — four handout experiments have no shipped code:** the `<eos>`-honouring
decoder comparison (73 single-character / 5 empty), the 200-string OOV batch, the
cosine-similarity analysis, and the x ∈ 1..999 retrain (`XALL = 1:99` and the
two-digit prompt format are hard-coded). Either implement them or strip their numbers
from the handout; at present they are unreproducible by construction.

**Minor.** (1) The equation table misquotes line 160 (drops `+ realmin`) and hides
the `Zs` max-subtraction and the `/n` rescale; `z = We + b` is literal only at
DEPTH=0 — one footnote fixes all of it, and slides 18/20 of the new section should
carry that footnote when the "equation is the code" claim is made. (2) Figure legends
label teacher-forced held-out loss and free-running accuracy identically; one line of
protocol labelling needed. (3) Internal inconsistencies: "~250 lines" vs 419;
"~4,000 parameters" vs 2,957; 12k vs 8k ITER between handout and worksheet; OOV seed
list 0/1/3; dead `E4p` in the sweep; "learned embeddings" in the
identical-to-production list overstates one-hot inputs. (4) He initialisation paired
with tanh: harmless at this scale (layer-1 pre-activation std 0.39); flag only if a
slide ever names the scheme.

**Adopted change for slide 19** (reviewer's sketch, ~10 lines, evaluation stays
greedy so no published curve moves). Two parameters after `ETA` in `llm_lab.m`:

```matlab
TEMP  = 0;   % decoding temperature [-]; 0 = greedy argmax, >0 samples from P.^(1/TEMP)
DSEED = 0;   % decoding RNG seed [-], separate from SEED; training untouched
```

In `gen_trace` (signature extended to accept TEMP), replacing the argmax at line 389:

```matlab
if TEMP <= 0
    [~, nx] = max(P);                     % greedy: argmax_v P(v|ctx)
else
    q  = P .^ (1/TEMP);  q = q/sum(q);    % equals softmax(z/TEMP), renormalised
    nx = find(cumsum(q) >= rand, 1);      % categorical sample via inverse CDF
end
toks(k) = nx;  S = [S, nx];
```

plus `rng(DSEED)` (printed) in the prompt loop before each `gen_trace` call. Same
DSEED reproduces the output; a new DSEED varies it at unchanged distribution — the
slide-19 worked example, live. Breakage: none structural (`gen_batch` and
`heldout_loss` stay greedy); two documentation lines become conditional on TEMP=0
(handout "bit-identical run", worksheet "Decoding is greedy").

<!-- decision: llm-lab-act-switch | status: rejected | supersedes: none -->
**Rejected: an ACT ('tanh'|'relu'|'sigmoid') parameter** for slide 14. Reasons: the
backward pass hard-codes tanh′ at three call sites across three files, so the switch
dilutes the "six lines is the whole model" claim; every handout number would need
re-verification per activation; ReLU at full-batch ETA=0.5 risks dead-unit stalls
live, an untested failure mode; and on rules the model solves to 100 % the curves are
near-identical — nothing visible to point at. A ten-line standalone activation plot
serves slide 14 better.

**Notation alignment (optional, before the demo):** on-screen strings a student will
read against the slides — `P(v | ctx)` vs $P(x_{k+1}{=}v\,|\,\mathbf{x}_{1:k};\theta)$
(`llm_lab.m:134, 247`), `ETA` vs $\eta$, `KMAX` vs $k$, `training positions` vs
$|\mathcal{D}|$, and no panel ever shows pre-softmax $\mathbf{z}$ (worth one added
fprintf if slide 18 is demoed). Already aligned: `|theta|`, `L(theta*)`,
`L(θ) [nats]`, `v ∈ V`.
